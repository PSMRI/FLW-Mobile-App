## 1. Rules agreed with Nikhil
1. **XML only, no Compose.** Only the look changes; logic, DB, APIs stay the same.
2. **Translate Figma exactly, like a developer** — read real numbers from Figma, never eyeball. Verify on the real phone by screenshot and measure (px ÷ 2 = dp on the test phone).
3. When both exist, use the **original phase-1 frames** (`01 · Login`, `02 · Home – Today`, `03 · Home – Modules`, `04 · Households`, `05 · Household members`, `06 · All beneficiaries`, `07 · Register member`, `08 · Sync`, `09 · Profile & more`). Use the `M2.x-NN` frames for screens that only exist there. Code behaviour wins over Figma where they differ (Figma yellow "RULES (from code)" notes say what).
4. Keep every view **id** the Kotlin uses. Old layout is kept as `res/layout/legacy_<name>.xml` (not inflated). Old code lines are **commented, not deleted**.
5. **Do not use the emulator.** Use Nikhil's phone (USB, adb).
6. Every new Hindi / Assamese / Bangla text is a draft → needs native-speaker review.

## 2. How to work a screen (the loop)
1. **Get the exact Figma spec** with the local plugin (Figma desktop must be open on the file and in front):
   - set the frame in `design/figma-plugin/src/50-stage-spec.js` → `const SPEC_FRAME = '<frame name prefix>';`
   - `src/90-main.js` → `const CURRENT_STAGES = ['spec'];`
   - `cd design/figma-plugin && node build.js`
   - Figma menu: **Plugins → Development → FLW Redesign Builder → Phase 2: build current stage(s)** → a "Spec dump" text appears on the Screens page (x, y, w×h, padding, gap, radius, fill, stroke, font size/line-height/weight for every layer).
   - **Exact spec as text (preferred, added 2026-11-06):** start `python3 -I design/figma-plugin/spec_receiver.py <out.txt>` first —
     the spec stage then POSTs the full dump to `http://localhost:8765` (dev-only `devAllowedDomains` in manifest.json) and it lands in `<out.txt>`.
     Plugin errors are sent the same way (`ERROR …`). Menu click from the terminal:
     `osascript -e 'tell application "System Events" to tell process "Figma" to click menu item "Phase 2: build current stage(s)" of menu 1 of menu item "FLW Redesign Builder" of menu 1 of menu item "Development" of menu 1 of menu bar item "Plugins" of menu bar 1'`
     (Figma window screenshots don't work from the terminal here — this replaces them.)
   - Helper scripts (scratchpad, may be gone after reboot): `runfig.sh` (clicks the menu via osascript), `shot.sh` / `winid` (window screenshot). Recreate if missing (see FIGMA_REDESIGN_PLAN.md §4A.6).
   - Other utility stages: `'tokens'` (all colours/text styles), `'ids'` (node ids for share links).
2. **Write the XML** using the design tokens (section 4).
3. **Build & install on the phone** (keeps app data):
   ```
   ./gradlew :app:assembleSakshamUatDebug --offline -q
   adb install -r -t app/build/outputs/apk/sakshamUat/debug/app-sakshamUat-arm64-v8a-debug.apk
   adb shell am force-stop org.piramalswasthya.sakhi.saksham.uat
   adb shell monkey -p org.piramalswasthya.sakhi.saksham.uat -c android.intent.category.LAUNCHER 1
   adb exec-out screencap -p > shot.png
   ```
   Test phone: Lava LZX408, 720×1600 @ 320 dpi = **360×800 dp (same as the Figma frames)**. It has `saksham.uat` (Studio-signed → `install -r` works, data kept) and `mitanin.uat` (CI-signed → can't overwrite). Phone must be unlocked.
4. **Measure** the screenshot against the spec, fix, repeat. Also check: keyboard open, scrolling, background, status bar.
5. Before finishing a batch also compile Mitanin resources: `./gradlew :app:processMitaninUatDebugResources --offline -q`.

## 5. Gotchas found
- A view id in both `layout/` and `layout-sw600dp/` must keep a compatible class (CheckBox vs MaterialCheckBox broke the build).
- Android trims trailing spaces in strings → use ` `.
- Apostrophes in strings → use `’` (typographic) or escape.
- Material chips add a 6 dp invisible touch margin → `ensureMinTouchTargetSize=false` for exact Figma height.
- Material CheckBox ignores padding for the box → use `button=@null` + `drawableStart` (custom `ic_ds_checkbox*`).
- Don't run a Gradle build while still editing layouts (data-binding errors cascade); check the latest full build.
- `app/src/main/cpp/native-lib.cpp` was already modified before this work — not part of the redesign.
- Figma buttons with a fixed width centre their content: the "padding 24" in the spec is not the real side gap — use 16 dp or the label gets cut ("Add Member" → "Add").
- Never `setBackgroundColor` on a `MaterialCardView` — it drops the border and corners; use `setCardBackgroundColor`.
- Module titles contain `\n` (made for the old centred tiles) — flatten them wherever a one-line title is shown.
- The app's "Screen overlay detected. Action blocked." guard can swallow an `adb input tap`; just tap again.
- **A style for a button / radio / checkbox created in code must have a real parent** (e.g. `Widget.AppCompat.CompoundButton.RadioButton`).
  `RadioButton(ctx, null, 0, R.style.X)` with `parent=""` loses `clickable/focusable` → options can't be tapped (bug found 2026-11-06, fixed).
- Test every restyled control by **using** it (tap, select, type, dependent fields hide/show), not only by screenshot.
- **Legacy `MaterialButton.setBackgroundColor(red)` survives a later `backgroundTintList = X`** when X is the same
  (cached) list the style already set — MaterialButton skips an "unchanged" tint. `dsFormState` resets to `null` first
  (found 2026-11-06 on HRP: "not started" stayed red). Old code is left in place, the ds call simply runs after it.
- Three weighted buttons in one card row truncate ("Micro Bi…"): use `wrap_content` + weight 1 (content first, then
  share the rest) and make secondary actions icon-only (HRP Share = 48 dp WhatsApp button).
- `timeout` doesn't exist on macOS — a `timeout … ./gradlew` silently does nothing (error hidden by the grep filter).
